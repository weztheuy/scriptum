# Карта страниц:

```
/
├── /auth
│   ├── /login
│   └── /register
├── /works
│   ├── /new
│   └── /:id
│       ├── /edit
│       ├── /download
│       └── /chapters
│           ├── /new
│           └── /:chapterId
│               └── /edit
├── /authors
│   └── /:id
│       ├── /bookmarks
│       └── /read-works
└── /account
    ├── /profile
    ├── /privacy
    └── /security
        ├── /password
        └── /delete-account
```


# Список маршрутов:

## Аутентификация:
- /auth/login — вход
- /auth/register — регистрация

## Произведения:
- /works — каталог произведений (поиск, фильтрация с пагинацией)
- /works/new — публикация новой работы (с названием, описанием, обложкой, жанрами, метками)
- /works/:id — страница произведения (с названием, описанием, обложкой, жанрами, метками, оценкой, списков добавления в коллекции, комментариями с пагинацией и ссылкой на список глав)
- /works/:id/edit — редактирование основных данных произведения (с названием, описанием, обложкой, жанрами, метками)
- /works/:id/download — скачивание произведения

## Главы:
- /works/:id/chapters — список главы произведения
- /works/:id/chapters/new — добавление новой главы (с названием, содержанием и выбором позиции)
- /works/:id/chapters/:chapterId — страница конкретной главы (с названием, содержанием, переключателем метки прочитанного, комментариями с пагинацией, ссылками на соседние главы)
- /works/:id/chapters/:chapterId/edit — редактирование главы (с названием, содержанием и выбором позиции)

## Авторы:
- /authors — список пользователей (только поиск)
- /authors/:id — страница пользователя (с публичным именем, описанием)
- /authors/:id/bookmarks — закладки пользователя
- /authors/:id/read-works — список прочитанных работ

## Пользователь:
- /account — список разделов настроек
- /account/profile — управление профилем (публичное имя, описание)
- /account/privacy — настройки приватности (публичность закладок, прочитанного)
- /account/security/password — смена пароля (старый пароль, новый пароль, подтверждение нового пароля)
- /account/security/delete-account — удаление аккаунта (пароль, подтверждение пароля)

## Примечание:
- Для пагинации комментариев используется query string: /works/:id?comments_page=2
- Для ссылки на конкретный комментарий используется hash-link: /works/:id#comment-789


# Особенности архитектуры платформы

## Комментарии
- Комментарии к произведениям и главам загружаются на соответствующих страницах
- Пагинация комментариев через API (загрузка по 10 комментариев)
- Сортировка комментариев: от старых к новым (страница 1 — самые ранние)
- Ссылки на комментарии: hash-link формата `#comment-{id}`
- При переходе по hash-link происходит определение нужной страницы через API
- Линейная система комментариев (без древовидной структуры)
- Возможность ссылаться на другие комментарии через форматирование (>>ID)

## Главы и произведения
- Порядок глав определяется числовым полем position
- При изменении позиции главы пересчитываются позиции других глав
- Отметка прочитанных глав через отдельную кнопку на странице главы
- Статус прочтения отображается на странице списка глав

## Навигация и UX
- Поиск и фильтрация в каталоге /works через query string: `?q=...&genre=...`
- Пагинация каталога /works через query string: `?page=2`
- Прямые ссылки на произведения, главы, комментарии
- AJAX для пагинации комментариев и некоторых действий
- Полная загрузка страниц для SEO и прямых ссылок

## API
- RESTful API для комментариев, глав, произведений
- Эндпоинты для определения страницы комментария: `GET /api/comments/:id/page`
- Эндпоинты для пагинации комментариев: `GET /api/comments?target_type=...&target_id=...&page=...`

## Безопасность
- JWT для аутентификации
- Проверка прав доступа при редактировании/удалении
- Валидация (но пока без санитизации) пользовательского контента

## Масштабируемость
- Архитектура позволяет легко добавить:
  - Email
  - Уведомления
  - Древовидные комментарии
  - Подписки на авторов
  - Модерацию контента
  - Мультиязычность

## Технические детали
- SSR (Server-Side Rendering) для основных страниц
- AJAX для динамических элементов (комментарии, оценки)
- Использование реляционной СУБД
- Изменение позиций всех затрагиваемых глав через единый запрос (при надобности можно принять меры оптимизации)
